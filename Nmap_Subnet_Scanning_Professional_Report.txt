NETWORK SUBNET SCANNING REPORT Using Nmap and Wireshark

Prepared by: Shuvo Paul Assessment date: 05 November 2026 Environment:
Kali Linux Assessment scope: Local subnet 192.168.1.0/24

1.  EXECUTIVE SUMMARY

This report documents a subnet discovery and network-traffic observation
exercise conducted on the local network. Nmap was used to perform a TCP
SYN scan against the 192.168.1.0/24 subnet, while Wireshark was used to
observe the network traffic generated during the activity.

The Nmap output reports that 256 IP addresses were scanned and that zero
hosts were identified as up. The scan completed in 206.49 seconds.
Therefore, this scan did not identify any live hosts, and it did not
produce a list of discovered open ports. The accompanying Wireshark
screenshots show captured traffic during the exercise; however, the
screenshots alone do not establish which devices were successfully
discovered or which services were confirmed open.

2.  OBJECTIVE

The objective was to discover active devices and identify potentially
exposed TCP ports on the local network in order to gain an overview of
network exposure.

3.  TOOLS AND ENVIRONMENT

• Nmap: A network discovery and security auditing utility used to probe
hosts and ports. • Wireshark: A packet-capture and protocol-analysis
utility used to observe network traffic. • Operating system: Kali Linux.
• Target subnet: 192.168.1.0/24.

4.  METHODOLOGY

The following command was executed from the Kali Linux terminal:

    nmap -sS 192.168.1.0/24

The -sS option requests a TCP SYN scan. In this scan type, Nmap sends
TCP SYN probes to target ports and interprets the responses to assess
port states. The target notation 192.168.1.0/24 specifies the IPv4
subnet, covering 256 addresses (192.168.1.0 through 192.168.1.255).

Wireshark was also used to capture and inspect network packets during
the scanning activity. The screenshots included with the source material
document the packet-capture interface and traffic observed during the
exercise.

5.  RESULTS AND OBSERVATIONS

5.1 Nmap scan result

The terminal output recorded the following:

    Starting Nmap 7.991 at 2026-11-05 20:17 +0530
    Nmap done: 256 IP addresses (0 hosts up) scanned in 206.49 seconds

Key observations: • Total addresses scanned: 256. • Hosts reported as
up: 0. • Scan duration: 206.49 seconds. • Nmap version shown in the
output: 7.991.

No live hosts were reported by this scan. Consequently, the supplied
output does not identify any open, closed, or filtered ports on target
hosts. It would be inaccurate to conclude from this result that the
subnet contains no devices or that all devices have no open ports.
Devices may not have responded to the probes, may be protected by
firewalls, or the scan may have been run from a network segment with
limited visibility.

5.2 Wireshark observations

The source document contains Wireshark screenshots on pages 1 and 2.
They show the packet-capture interface with multiple captured entries
and packet details. These screenshots provide visual evidence that
traffic was being observed during the exercise.

The supplied screenshots do not provide a sufficiently clear, readable
record of all packet fields, endpoints, protocol details, or a complete
capture summary. Accordingly, this report does not assign specific
devices, ports, or protocol findings based solely on the screenshots.

6.  ANALYSIS

The Nmap result is inconclusive for host and port discovery because no
hosts were reported as up. A successful subnet assessment normally
requires confirming that the scanner can reach the intended network and
that target devices are able to respond to discovery probes.

Possible explanations for the zero-host result include: • The target
subnet may not match the actual local network interface configuration. •
The scanner may be connected to a different network, VLAN, or
virtual-machine network mode. • Host firewalls or network security
controls may block discovery probes. • Devices may be offline or
configured not to respond to the probes used. • The virtual machine may
have limited network connectivity or an unsuitable adapter
configuration.

These are possible causes, not confirmed findings. The supplied evidence
does not identify which explanation applies.

7.  RECOMMENDATIONS AND NEXT STEPS

8.  Verify the Kali Linux network configuration using commands such as:

        ip addr
        ip route

    Confirm the active interface, assigned IP address, subnet mask, and
    default gateway. Ensure that 192.168.1.0/24 is the correct subnet
    for the connected network.

9.  Confirm basic connectivity to the local gateway and verify that the
    Kali machine is connected to the intended network.

10. If Kali Linux is running in VMware, check the virtual network
    adapter mode and confirm that it provides access to the network
    being assessed.

11. Repeat host discovery on the authorized subnet after confirming the
    network configuration. For example:

        nmap -sn 192.168.1.0/24

    This performs host discovery without a port scan. Use it only on
    networks for which permission has been granted.

12. If host discovery still reports no live hosts, investigate firewall
    rules, VLAN separation, wireless client isolation, and virtual
    network settings before interpreting the result.

13. Once live hosts have been identified, perform a targeted port scan
    against those authorized hosts. Record the exact command, target
    addresses, scan time, and complete Nmap output.

14. In Wireshark, select the correct active interface before capturing.
    Save the capture as a PCAPNG file and use suitable display filters
    to inspect relevant traffic. Preserve the capture file so that
    packet-level findings can be verified.

15. Document confirmed open ports together with the associated host IP
    address, service identification, and evidence. Do not describe a
    port as open unless the scan output supports that conclusion.

16. LIMITATIONS

• The available Nmap output reports zero hosts up; therefore, no
host-specific port findings can be reported. • The source material does
not include a detailed Nmap scan report for individual hosts or ports. •
The Wireshark evidence is supplied as screenshots rather than a complete
PCAP/PCAPNG capture file. • The screenshots do not provide enough
readable detail to validate individual endpoints, port numbers, or
protocol-level conclusions. • Potential causes of the zero-host result
are discussed as possibilities and have not been verified.

9.  CONCLUSION

The exercise demonstrated the use of Nmap for subnet scanning and
Wireshark for observing network traffic in a Kali Linux environment. The
command nmap -sS 192.168.1.0/24 scanned 256 addresses and completed in
206.49 seconds, but reported zero hosts up. As a result, the available
evidence does not confirm any active hosts or open ports on the target
subnet.

The next step is to verify the local network configuration and
virtual-machine connectivity, then repeat host discovery and conduct
targeted port scans against authorized devices. A complete packet
capture and full scan output should be retained to support any final
security assessment.
